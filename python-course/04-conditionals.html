Conditionals — teaching your program to decide

Every program you've written so far runs top to bottom, no matter what — every line executes, every single time. Real decisions aren't like that. "If it's raining, take an umbrella, otherwise don't" only runs one of those two actions, depending on the actual weather. Conditionals are how you write that kind of logic in Python.

if, elif, else

pythonage = int(input("How old are you? ")) if age >= 18: print("You can vote.") elif age >= 13: print("You're a teenager.") else: print("You're a kid.")

Python checks each condition in order, top to bottom, and the instant one is True, it runs that block and completely skips the rest — so if age is 20, it never even looks at the elif or else lines. Think of it like a row of doors: Python opens the first one that says "yes," walks through, and doesn't check any door after that.

Why indentation matters here

Notice that print("You can vote.") is indented — pushed in with spaces — under the if line. That indentation is not just for looks. It's how Python knows that line belongs to the if block, instead of being a separate instruction that runs regardless. Some languages use curly braces { } for this; Python uses indentation itself as the structure.

💡 Trick that will catch you at least once: mixing tabs and spaces, or forgetting to indent a line that should be inside the block, causes an IndentationError. Most code editors handle this automatically once you press Tab — but it's worth knowing why that error exists the first time you see it, instead of assuming your code is broken in some mysterious way.

Combining conditions

Sometimes one comparison isn't enough — you need two or more conditions to be true (or just one out of several) before the program should act.

  1. 1

    and — both must be true

    The whole condition is only True if every single part of it is true. If even one side is False, the whole thing is False.

    age >= 13 and age <= 19 → checks if someone is a teenager — both boundaries must hold
  2. 2

    or — at least one must be true

    Only needs one side to be true for the whole thing to pass — it doesn't care if the other side is false.

    day == "Saturday" or day == "Sunday" → checks for a weekend
  3. 3

    not — flips it

    Takes whatever a condition would normally return and reverses it — True becomes False and vice versa.

    not is_raining → True exactly when is_raining is False

Nesting conditionals

You can put an if inside another if, when one decision only makes sense to check after another one has already been decided.

pythonmarks = int(input("Enter your marks: ")) if marks >= 40: print("You passed.") if marks >= 90: print("And with distinction!") else: print("You didn't pass this time.")

The distinction check only happens inside the "passed" branch — notice it's indented one level further than print("You passed."). It never even runs if the person failed, because checking for a distinction on a failing score wouldn't make sense.

Putting it together: a grade calculator

pythonmarks = int(input("Enter your marks out of 100: ")) if marks >= 90: grade = "A+" elif marks >= 80: grade = "A" elif marks >= 70: grade = "B" elif marks >= 60: grade = "C" elif marks >= 40: grade = "D" else: grade = "F" print(f"Your grade is: {grade}")
💡 Trick: notice the order — checking from highest to lowest. If you checked marks >= 40 first instead, every single score above 40 would stop right there and always show "D," since Python stops at the first True it finds and never looks further. The order you write conditions in genuinely changes the result, not just the style of the code.

🧩 Practice

Exercise 1 — Easy

Write a program that asks for someone's age and prints "Child" if under 13, "Teenager" if 13–19, and "Adult" if 20 or older.

pythonage = int(input("Enter your age: ")) if age < 13: print("Child") elif age <= 19: print("Teenager") else: print("Adult")
Exercise 2 — Predict the output

Without running it, work out what this prints:

pythontemperature = 15 is_raining = True if temperature > 20 and not is_raining: print("Great day for a walk") elif temperature > 20 or is_raining: print("Bring a jacket or umbrella") else: print("Stay inside")

"Bring a jacket or umbrella" — the first condition fails because temperature > 20 is false (15 isn't above 20), so Python moves to the elif. There, is_raining is True, and since it's an or, only one side needs to be true for the whole thing to pass.

Exercise 3 — Find the bug

This code always prints "Pass," even for very low marks. Figure out why, then fix it.

pythonmarks = int(input("Enter marks: ")) if marks >= 0: print("Pass") elif marks >= 40: print("Also technically pass") else: print("Fail")

marks >= 0 is true for almost any mark someone could realistically enter, so it always wins first — the same "wrong order" trap from the grade calculator above. The actual passing check needed to come first:

pythonmarks = int(input("Enter marks: ")) if marks >= 40: print("Pass") else: print("Fail")
